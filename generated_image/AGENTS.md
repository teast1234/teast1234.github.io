# 奶蛙名画生成 Agent 规则

适用范围：本目录中的奶蛙艺术绘画、增强、归档和质量验收。更新日期：2026-10-10。

- 用户已认可本目录三幅作品及其细节增强版：蒙娜丽莎、雅典学院、星月夜。以这些作品为效果基准；优先最高画质、精细笔触和角色一致性。
- 开工先读 `D:\myblog\docs\奶蛙AI视频生成手册.md` 的角色部分，并实际查看标准三视图和 3D 设定。
- 标准参考：`D:\myblog\generated_videos\refs\naiwa_standard_turnaround.png`、`naiwa_standard_3d.jpg`。外形以标准设定为准；构图和艺术语言以名画与用户参考为准。
- 身份必须保留：金黄梨形、无脖、奶油色圆肚、翠绿虹膜与黑瞳、细短嘴线、深灰褐手脚、每手四指、每脚三趾。禁止绿皮写实青蛙、Pepe、奶龙圆球化和人脸替换。
- 用户2026-10-10最新调整：“不需要刻意在意奶蛙的三指或者四指了，只要尽量靠就行了，不然要修改太多次了。”四指手、三趾脚仍是提示词中的参考目标，不再是严格数量验收门槛；优先整体艺术效果、奶蛙辨识度、原画姿态与构图。不因轻微指趾偏差或小尺度不可辨而反复重绘，不为数指强行展开手掌或改成标准站姿；明显多余肢体、严重畸形或角色漂移仍需修正。此最新授权取代此前严格数指规则，已认可图片不因它重做。
- 普通生成与编辑优先使用内置 `image_gen`；用户明确禁止使用 Poe，不调用其接口、模型或密钥。无需额外 API Key。
- 所有角色、服饰、环境必须使用统一绘画媒介；避免油画背景上贴光滑 3D 玩具。保留原作主题、空间秩序与关键手势。
- 最高质量不等于最大文件尺寸。优先真实细节、正确结构、绘画统一性，再提高像素尺寸；避免强锐化、光晕、伪纹理和人物结构漂移。
- 内置工具目前没有分辨率或质量参数；提示词中的 4K/8K 不代表实际输出。必须读取最终图片尺寸后报告，不承诺未知上限。
- 需要更大图时先核实可用超分辨率工具；保留原图，单独保存放大版，明确模型、倍率及来源。放大像素不能称为原生分辨率或真实新增细节。
- 每幅图单独生成、单独检查；增强尽量保留构图、配色、角色比例和姿势，不能把重绘声明为逐像素保真。
- 最终图片保存至 `D:\myblog\generated_image`，原图和衍生版分目录，禁止覆盖已认可版本。
- 每次交付记录实际工具、源图、尺寸、SHA256、版本、验收结果。模型 ID 未公开时写“未公开”，不能猜测。
- 完成前检查文件可解码、数量、尺寸、哈希，以及实际画面中的眼睛、手脚、人物脸、建筑透视、笔触和无意文字。
- 不把脚本成功或自动评价等同于人工逐图检查；客观说明仍有的问题与能力限制。
- 文本采用 UTF-8 无 BOM；Python 显式使用 `py -3.12`，读写显式指定编码，运行依赖型任务前预检解释器和依赖。

具体流程、已认可版本和尺寸见 `奶蛙艺术生图Agent手册.md` 与 `manifest.json`。

## 名画＋奶娃待办管理

- 先从 `04_名画创作清单/待创作名画总名单.md` 或对应方向 `待创作名画.md` 选题，并核实原作版本与图像来源。
- `作品状态总库.json` 为唯一状态源；按稳定编号管理。成功作品从待办移除并进入已完成档案，不能删除其成图或来源记录。
- “成功”需实际视觉验收并有用户认可或明确授权验收依据；不能把生成成功等同于验收成功。
- 使用 `管理创作清单.py complete` 登记，完成后同步全部分类名单；每次保存前自动备份。不要并行写总库，不直接手工只删Markdown。
- 蒙娜丽莎、雅典学院、星月夜已获用户认可并归档，不再作为待创作项。原六张图片和来源保留。
- 系列条目需先选版本或定义整组范围，不能以一幅代表整套完成。抽象艺术需明确奶娃身份如何保留。

## 奶娃作品命名（每幅创作后必须执行）

- 每幅奶娃作品创作后，Agent 必须结合原作标题、画面主题与奶娃角色主动思考，并选出一个正式作品名；不得仅以“原作名＋奶蛙”或文件编号作为交付名称。
- 命名优先简洁、顺口、有艺术意味和适度幽默，让人能联想到原作；可用“奶”“奶蛙”“奶娃”进行谐音、替换或主题化改写，但不机械套词。
- 用户给出的命名范例：蒙娜丽莎 →《蒙娜丽奶》；雅典学院 →《奶蛙学院》；星月夜 →《星月奶》。这三幅现有作品采用这些正式名称。
- 交付时展示正式作品名；归档同时保留原作标题、作者、稳定编号与成图路径。正式名称不能替换待办总库中用于追溯的原作字段。
- 在作品记录中使用独立的 `creation_title` 字段保存正式名称；同一作品的原版、增强版、超分版沿用同一正式名称，通过版本字段区分。
- 避免同名冲突、冗长标题和牵强谐音。用户另有指定名称时，以用户指定为准；通常由 Agent 直接选定，不为例行命名单独打断用户。
- 命名属于交付准备，不等同于验收成功；仍需满足原有成功标准后才能移出待创作名单。除非用户要求，不把作品名生成到画面中，也不为命名改动或覆盖已认可图片。

## 奶蛙画作背景介绍（每幅创作后必须执行）

- 每幅交付包括成图、正式作品名和背景介绍；以真实史料为基础，把原作主题与奶蛙自然融合成虚拟作品故事。不拆分史实与二创，不反复加虚构说明。
- 正文默认中文约150—300字，以实际成画中的奶蛙动作、环境和情绪为依据；避免百科粘贴、机械换名、模板填充及不存在的画面细节。
- 保存 `creation_background`、`background_sources` 和独立 `creation_title` 字段，保留原作标题、作者、年代、版本与来源追溯。对应方向06_验收归档保存同编号作品介绍Markdown。
- 缺少背景介绍或正文与成画不符时不能登记为完整交付；已认可作品补齐文字，不覆盖图片或撤销认可。
- 用户2026-10-10已明确授权Agent持续创作并自行逐图验收，不再逐批等过关。生成、命名、背景介绍、视觉与文件检查均通过后串行登记；用户叫停时停止。
- 具体写作和归档要求见奶蛙艺术生图Agent手册.md“画作背景介绍”章节。
